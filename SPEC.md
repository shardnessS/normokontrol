# ТЗ: normokontrol — набор скиллов Claude для оформления и проверки работ по ГОСТ

> Документ для поэтапной разработки в Claude Code.
> Работаем строго по этапам из раздела 10. После каждого этапа: тесты зелёные, чекбоксы отмечены, коммит, короткий отчёт пользователю, ждём подтверждения на следующий этап.

---

## 1. Цель и позиционирование

**Что делаем.** Открытый набор скиллов (Agent Skills) для Claude, который:
1. **Оформляет** учебную/научную работу (курсовую, ВКР, реферат, отчёт) по ГОСТ 7.32-2017 и методичке конкретного вуза: из Markdown/текста собирает готовый `.docx` (и `.pdf`).
2. **Оформляет список литературы** по ГОСТ Р 7.0.100-2018 из DOI, ISBN, URL или структурированных данных.
3. **Проверяет** готовый `.docx` как нормоконтролёр и выдаёт отчёт с конкретными нарушениями.
4. **Исправляет** то, что можно исправить автоматически.
5. **Отвечает на вопросы** о требованиях ГОСТ и методичек со ссылками на пункты.

**Где работает.** claude.ai и Claude Desktop (скиллы загружаются zip-архивами), Claude Code (плагин из GitHub). Проектируем под более строгую среду — песочницу claude.ai: что работает там, работает и в Claude Code.

**Позиционирование.** Инструмент *оформляет*, а не пишет работу за студента. Это прямо сказано в README и в каждом SKILL.md. Никаких функций генерации содержания работы.

**Ключевой принцип архитектуры.** Нечёткую работу (разобрать «грязный» текст ссылки, понять структуру черновика, объяснить ошибки) делает Claude по инструкциям скилла. Всё оформление и проверку делают **детерминированные Python-скрипты** внутри скиллов; Claude запускает их и передаёт результат пользователю без изменений. Результат одного и того же входа всегда одинаковый.

**Целевая аудитория.** Студенты и преподаватели вузов РФ (в v2 — СНГ), научные сотрудники.

**Название.** `normokontrol` (транслитерация «нормоконтроль» по ГОСТ 7.79-2000, система Б). Скиллы: `gost-rules`, `gost-bibliography`, `gost-document`, `gost-normokontrol`. Обоснование — в `docs/decisions.md`.

## 2. Нормативная база

| Стандарт | Что регулирует | Где используем |
|---|---|---|
| ГОСТ 7.32-2017 | Структура и оформление отчёта о НИР (де-факто база для ВКР и курсовых) | Пресет `gost-7.32-2017`, форматтер, проверка |
| ГОСТ Р 7.0.100-2018 | Библиографическое описание (действует с 01.07.2019, с Поправкой 2020) | Модуль `bibliography` |
| ГОСТ Р 7.0.5-2008 | Библиографические ссылки в тексте | Формат ссылок `[1, с. 15]` |
| ГОСТ Р 7.0.108-2022 | Ссылки на электронные ресурсы | Описание URL-источников |
| ГОСТ 7.1-2003 | Старое описание; в РФ не применяется с 2020, но действует в ряде стран СНГ | v2, пресеты СНГ |

**Важно:**
- Правила ниже в разделе 5 составлены по памяти и открытым источникам. **На этапе 1 каждое правило сверить с официальным текстом стандарта.** В пресете у правила есть поле `source` со ссылкой на пункт стандарта.
- Полные тексты ГОСТов в репозиторий **не кладём** (авторское право). Правила формулируем своими словами, указываем номер пункта.

## 3. Технологический стек

| Компонент | Выбор | Зачем |
|---|---|---|
| Формат | Agent Skills: папка со `SKILL.md`, `scripts/`, `references/` | Подключается в claude.ai, Claude Desktop, Claude Code |
| Язык скриптов | Python 3.11+ | Лучшие библиотеки для docx; есть в песочнице claude.ai |
| Зависимости ядра | Только пакеты, предустановленные в песочнице claude.ai (проверяется на этапе 3): ожидаемо `PyYAML`, `python-docx`, `lxml`; `pydantic` — если есть | В песочнице нельзя рассчитывать на установку пакетов из сети |
| Запуск скриптов локально | `uv run` с зависимостями в заголовке скрипта (PEP 723), иначе `python` | Claude Code без ручной установки пакетов |
| Модели/валидация | `pydantic` v2, если доступен в песочнице; иначе dataclasses + своя валидация | Схемы пресетов и источников |
| Конфиги | `PyYAML` | Пресеты вузов |
| Markdown → docx | Решается на этапе 5: pandoc (есть в песочнице claude.ai, локально — не всегда) или чистый `python-docx` | Таблицы, картинки, формулы |
| Постобработка docx | `python-docx` + прямой доступ к XML (`lxml`) | Поля, стили, нумерация, колонтитулы |
| Титульник | `python-docx` (шаблоны `.docx` с полями-заменителями) | Без `docxtpl`: меньше зависимостей |
| HTTP | `urllib` из стандартной библиотеки | Crossref (DOI), Open Library (ISBN), мета-теги URL |
| PDF и обновление оглавления | LibreOffice headless (есть в песочнице claude.ai; локально опционально) | Если нет — работает без PDF |
| Разработка | `uv`, `pytest`, golden-файлы, `ruff`, `mypy` | |
| Сборка и CI | GitHub Actions: lint + типы + тесты (Linux/macOS/Windows), сборка zip-архивов скиллов | |

## 5. Правила оформления (база пресета gost-7.32-2017)

> Сверено с текстом ГОСТ 7.32-2017 (раздел 6) на этапе 1. В скобках — пункт стандарта.
> Пометка **[не ГОСТ]** — требование не из стандарта, а типовое требование методичек вузов; в пресете оно помечено так же.

**Страница**
- Формат A4 (6.1.1), книжная ориентация.
- Поля: левое 30 мм, правое 15 мм, верхнее и нижнее 20 мм (6.1.1).

**Текст**
- Цвет шрифта чёрный, размер не менее 12 пт; рекомендуемый шрифт — Times New Roman (6.1.1). Базовый пресет использует 14 пт — **[не ГОСТ]**, типовое требование вузов; минимум 12 пт — из ГОСТ.
- Полужирный шрифт — только для заголовков разделов, подразделов и структурных элементов (6.1.1).
- Межстрочный интервал 1,5 (6.1.1); абзацный отступ 1,25 см, одинаковый по всему тексту (6.1.1).
- Выравнивание по ширине — **[не ГОСТ]**.
- Интервалы до/после абзаца 0 — **[не ГОСТ]**.

**Структурные элементы** (6.2.1): СПИСОК ИСПОЛНИТЕЛЕЙ, РЕФЕРАТ, СОДЕРЖАНИЕ, ТЕРМИНЫ И ОПРЕДЕЛЕНИЯ, ПЕРЕЧЕНЬ СОКРАЩЕНИЙ И ОБОЗНАЧЕНИЙ, ВВЕДЕНИЕ, ЗАКЛЮЧЕНИЕ, СПИСОК ИСПОЛЬЗОВАННЫХ ИСТОЧНИКОВ, ПРИЛОЖЕНИЕ. Пресет вуза может заменить список (например, «СПИСОК ЛИТЕРАТУРЫ»).
- Посередине строки, прописными буквами, без точки в конце, не подчёркивая (6.2.1); полужирным (6.1.1); без номера.
- Каждый начинается с новой страницы (6.2.1).

**Разделы основной части**
- Номер арабскими цифрами без точки, с абзацного отступа: `1 Анализ предметной области`; подраздел `1.1 Обзор …`, в конце номера точки нет (6.4.1).
- Заголовок с абзацного отступа, после номера, с прописной буквы, полужирным, не подчёркивая, без точки в конце (6.2.3). Несколько предложений разделяют точками; переносы не допускаются (6.2.4, 6.4.7).
- Каждый раздел с новой страницы (6.2.1), подразделы — нет.

**Нумерация страниц**
- Арабские цифры, сквозная, включая приложения; в центре нижней части страницы без точки (6.3.1).
- Титульный лист входит в нумерацию, номер на нём не ставится (6.3.2).

**Рисунки** (6.5)
- Подпись в центре под рисунком: `Рисунок 1 — Название`, с прописной буквы, без точки в конце (6.5.7, 6.5.8). Многострочное наименование — через один интервал, без переносов (6.5.8).
- Нумерация сквозная (6.5.4) или в пределах раздела `Рисунок 2.1` (6.5.6) — пресет. В приложениях: `Рисунок А.3` (6.5.5).
- На каждый рисунок должна быть ссылка: «в соответствии с рисунком 2» (6.5.1).

**Таблицы** (6.6)
- Наименование над таблицей слева, без абзацного отступа: `Таблица 1 — Название`, с прописной буквы, без точки; многострочное — через один интервал (6.6.3).
- При переносе над продолжением слева: `Продолжение таблицы 1` (6.6.3). Повтор шапки — наш выбор реализации; ГОСТ допускает и замену шапки номерами граф.
- Нумерация сквозная или в пределах раздела `Таблица 2.3`; в приложениях `Таблица А.1` (6.6.4).
- На каждую таблицу — ссылка в тексте (6.6.2). Размер шрифта в таблице может быть меньше, чем в тексте (6.6.7).

**Формулы** (6.8)
- Отдельной строкой, выше и ниже — не менее одной свободной строки (6.8.1).
- Посередине строки, номер в круглых скобках в крайнем правом положении: `(1)`; нумерация сквозная (6.8.3) или в пределах раздела `(3.1)`; в приложениях `(В.1)` (6.8.5). Ссылка: «в формуле (1)» (6.8.4).
- Пояснение символов — с новой строки, первая строка начинается со слова «где» без двоеточия, с абзаца (6.8.2).

**Ссылки и список источников**
- Номер ссылки арабскими цифрами в квадратных скобках (6.9.1); пример из стандарта: `[1]-[4]`, `[9], раздел 5` (6.9.3). Форма `[1, с. 15]` — по ГОСТ Р 7.0.5-2008, сверить на этапе 2.
- Источники — в порядке появления ссылок в тексте, нумерация арабскими цифрами с точкой, с абзацного отступа (6.16). Алфавитный порядок — только по пресету вуза.

**Приложения** (6.17)
- Каждое с новой страницы; в центре верхней части — `ПРИЛОЖЕНИЕ А`; заголовок — отдельной строкой по центру, с прописной буквы, полужирным, без точки (6.17.3).
- Буквы кириллицы с А, кроме Ё, З, Й, О, Ч, Ъ, Ы, Ь; допускается латиница, кроме I и O (6.17.4).
- На каждое — ссылка в тексте; располагаются в порядке ссылок (6.17.2). Нумерация страниц сквозная (6.17.6).

**Перечисления** (6.4.6)
- Перед каждым элементом — тире; если на элемент ссылаются — строчные буквы со скобкой `а)`, `б)` (кроме ё, з, й, о, ч, ъ, ы, ь); допускаются цифры со скобкой `1)`. С абзацного отступа, в столбик.

**Типографика** — **[не ГОСТ 7.32]**, правила русской типографики; в проверке — предупреждения, не ошибки.
- Тире `—` с пробелами в тексте; `–` в диапазонах чисел и страниц без пробелов.
- Кавычки «ёлочки», вложенные „лапки“.
- Нет двойных пробелов, пустых абзацев для отступов, ручных разрывов вместо разрыва страницы.
- Неразрывный пробел: между инициалами и фамилией, перед «с.», между числом и единицей.

**Решения пользователя** (2026-09-30):
- Знак в подписях `Рисунок 1 — …` — длинное тире `—`.
- Базовый пресет: кегль 14 пт и выравнивание по ширине остаются (с пометкой «Не ГОСТ»).

## 6. Модель пресета

Полный базовый пресет — `src/normokontrol/presets/data/gost-7.32-2017.yaml`, схема — `presets/schema.py`. Сокращённо:

```yaml
id: gost-7.32-2017            # совпадает с именем файла
name: ГОСТ 7.32-2017 (базовый)
country: RU
verified: true                # правила сверены с первоисточником
source_docs: ["ГОСТ 7.32-2017, раздел 6"]
page:
  size: A4
  orientation: portrait
  margins_mm: { left: 30, right: 15, top: 20, bottom: 20 }
text:
  font: Times New Roman
  size_pt: 14                 # размер при сборке
  min_size_pt: 12             # минимум по ГОСТ, для проверки
  color: "000000"
  line_spacing: 1.5
  first_line_indent_cm: 1.25
  align: justify
  space_before_pt: 0
  space_after_pt: 0
headings:
  structural_titles: [СПИСОК ИСПОЛНИТЕЛЕЙ, РЕФЕРАТ, …, ПРИЛОЖЕНИЕ]
  structural: { case: upper, align: center, bold: true, new_page: true }
  level1:     { case: first_upper, align: indent, bold: true, new_page: true,  number_format: "{n1}" }
  level2:     { case: first_upper, align: indent, bold: true, new_page: false, number_format: "{n1}.{n2}" }
page_numbers: { position: bottom-center, show_on_title: false }
figures:  { numbering: continuous, caption: "Рисунок {num} — {title}", position: below, caption_align: center, caption_line_spacing: 1.0 }
tables:   { numbering: continuous, caption: "Таблица {num} — {title}", continuation: "Продолжение таблицы {num}",
            position: above, caption_align: left, caption_line_spacing: 1.0, font_size_pt: 12 }
formulas: { numbering: continuous, format: "({num})", blank_line_around: true }
bibliography: { title: СПИСОК ИСПОЛЬЗОВАННЫХ ИСТОЧНИКОВ, order: by_citation, numbering: "{n}. ", standard: gost-r-7.0.100-2018,
                dash: "–", content_type: true }   # «. – » и область «Текст : непосредственный»
appendices: { title: "ПРИЛОЖЕНИЕ {letter}", letters: АБВГДЕЖИКЛМНПРСТУФХЦШЩЭЮЯ, new_page: true }
lists: { bullet: "—", letters: абвгдежиклмнпрстуфхцшщэюя }
title_page: { template: generic-student }
rules: { TYPO-003: warning }  # error | warning | info | off
sources:                       # откуда взят каждый параметр
  page.margins_mm: "ГОСТ 7.32-2017, п. 6.1.1"
  text.align: "Не ГОСТ: типовое требование вузов"
```

`{num}` в подписях — готовый номер объекта: его вид (`1`, `2.1`, `А.3`) определяет `numbering` и то, находится ли объект в приложении. Шаблоны проверяются: неизвестные или пропущенные поля — ошибка.

Пресет вуза:

```yaml
id: urfu-vkr-bachelor
name: УрФУ, ВКР бакалавра
extends: gost-7.32-2017
verified: false           # пока не сверен с актуальной методичкой
source_docs:
  - "Методичка кафедры …, 2025 (ссылка)"
figures: { numbering: per_chapter }
title_page: { template: urfu-vkr }
sources:
  figures.numbering: "Методичка …, п. 3.4"
```

**Требования к загрузчику:**
- `extends` — глубокое слияние (словари сливаются, списки и значения заменяются), цепочки наследования, защита от циклов.
- Не наследуются: `id`, `name`, `verified` (по умолчанию `false`), `source_docs`, `extends`.
- Если дочерний пресет меняет параметр, унаследованная ссылка на источник для него удаляется.
- Валидация pydantic с понятными сообщениями на русском.
- Пресеты пользователя можно подключить из своей папки через переменную окружения `NORMOKONTROL_PRESETS_DIR` (с подпапками). Совпадение id со встроенным пресетом — ошибка.

**Правила распознавания:**
- Заголовок `#` с текстом из списка структурных элементов → структурный элемент, без номера.
- Остальные `#` → раздел с номером, `##` → подраздел.
- `# ПРИЛОЖЕНИЕ` → приложение, буква проставляется автоматически, `##` внутри — его название.
- `[@fig:id]`, `[@tbl:id]`, `[@eq:id]`, `[@app:id]` → «рисунок 1», «таблица 1», «(1)», «приложение А» (падеж — по форме ссылки в тексте; в MVP просто номер).
- `[@key]`, `[@key, с. 15]` → `[n]`, `[n, с. 15]`, номер по порядку первого упоминания.
- Неизвестный id → ошибка с указанием строки.

## 8. Скиллы и скрипты

Общие требования:
- `description` в SKILL.md — на **английском** (по нему Claude решает, когда включить скилл), с русскими ключевыми словами запросов («оформи по ГОСТу», «список литературы», «нормоконтроль»). Инструкции в теле SKILL.md — на английском; сообщения пользователю и отчёты — на **русском**.
- SKILL.md короткий; подробности — в `references/` (Claude читает их по необходимости).
- В SKILL.md явно: результат скрипта выдаётся пользователю **без изменений**; Claude не дописывает и не «исправляет» оформление сам; недостающие данные спрашивает у пользователя, а не придумывает.
- Скрипты: вход — файл JSON/YAML или stdin, выход — текст или JSON (`--json`); код возврата 0 при успехе. Ошибки — структурированные: `{error_code, message_ru, location}`.
- Пути принимаются абсолютные или относительно рабочей папки. Исходник **никогда** не перезаписывается: результат пишется рядом с суффиксом (`работа_gost.docx`).
- Сеть используется только в `lookup.py`. Переменная `NORMOKONTROL_OFFLINE=1` отключает сеть. Если сети нет (песочница claude.ai), Claude находит данные источника своим веб-поиском, а скрипт только оформляет.

| Скилл | Когда срабатывает | Скрипты | Этап |
|---|---|---|---|
| `gost-rules` | Вопросы о требованиях ГОСТ 7.32 и методичек | `presets.py` (`list`, `rules <id>`, `yaml <id>`) | 3 |
| `gost-bibliography` | Список литературы, библиографическая запись, ссылки | `format_bibliography.py`, `lookup.py` | 3–4 |
| `gost-document` | «Оформи работу по ГОСТу», Markdown/черновик → docx | `build.py`, `title_page.py`, `export_pdf.py` | 5–6, 9 |
| `gost-normokontrol` | «Проверь перед нормоконтролем», исправить docx | `check.py`, `fix.py` | 7–8 |

Сценарии (бывшие промпты MCP) — часть инструкций SKILL.md:
- `gost-document`: спросить вуз/пресет, собрать front matter, запустить `build.py`.
- `gost-normokontrol`: запустить `check.py`, объяснить ошибки простыми словами, предложить `fix.py`.
- `gost-bibliography`: принять ссылки в любом виде, превратить в `Source` (Claude + `lookup.py`), запустить `format_bibliography.py`.

## 9. Проверка документа (checker)

### 9.1 Устройство
- Правило = функция `check(doc, preset) -> list[Violation]` + метаданные: `id`, `title_ru`, `severity` (`error | warning | info`), `fixable: bool`, `source` (пункт стандарта).
- `Violation`: `rule_id`, `message_ru`, `location` (номер абзаца, раздел, первые 60 символов текста), `expected`, `actual`.
- Номера страниц в docx без вёрстки неизвестны — указываем раздел и фрагмент текста. Если доступен LibreOffice — опционально добавляем номер страницы через экспорт.
- Отчёт в Markdown: сводка (ошибок/предупреждений), затем группировка по разделам документа.

## 11. Нефункциональные требования

- **Детерминизм:** одинаковый вход → побайтово одинаковый docx (фиксировать даты в метаданных docx, сортировку).
- **Производительность:** документ на 60 страниц собирается быстрее 10 секунд без PDF.
- **Кроссплатформенность:** Windows обязательно (большинство студентов). Пути через `pathlib`, кириллица в путях и именах файлов.
- **Безопасность:** скрипты не выполняют произвольных команд; subprocess только для pandoc/soffice с фиксированными аргументами; пути нормализуются; сеть только к Crossref/Open Library/URL источника; никакой телеметрии.
- **Приватность:** скрипты никуда не отправляют документы (кроме запросов метаданных по DOI/ISBN/URL). В claude.ai документ загружается в чат с Claude — это отмечено в README; в Claude Code файлы остаются на компьютере.
- **Зависимости:** ядро работает на пакетах, предустановленных в песочнице claude.ai; новая зависимость — только после проверки, что она там есть.
- **Покрытие тестами:** ≥ 85% для `bibliography` и `checker`.
- **Сообщения пользователю** — на русском, без технического жаргона; в каждом нарушении указано, что ожидалось и что найдено.
