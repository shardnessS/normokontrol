# Журнал архитектурных решений

Формат: дата — решение — причина.

## 2026-09-30 — Название `normokontrol-mcp`

Рабочее имя `gost-mcp` заменено на `normokontrol-mcp`.

- «GOST» неоднозначно (семейство криптоалгоритмов, прокси-проекты), на GitHub уже есть `mcp-gost` и `gost-standardizer-mcp`.
- «Нормоконтроль» точно описывает назначение инструмента; транслитерация по ГОСТ 7.79-2000 (система Б). Вариант `normocontrol` из черновика ТЗ — смесь транслитерации и английского.
- Имя свободно на PyPI и GitHub (проверено 2026-09-30).

Производные имена: пакет `normokontrol_mcp`, команда `normokontrol-mcp`, переменные окружения `NORMOKONTROL_*`, схема ресурсов `normokontrol://`.

## 2026-09-30 — MCP SDK 2.x: `MCPServer` вместо `FastMCP`

В `mcp` 2.x класс `FastMCP` переименован в `mcp.server.mcpserver.MCPServer`, API декораторов тот же. Используем `mcp>=2.2,<3`. В ТЗ «FastMCP» читать как `MCPServer`.

## 2026-09-30 — MCP Inspector на Windows и `uvx`

`npx @modelcontextprotocol/inspector --cli uvx --from . normokontrol-mcp` на Windows закрывает соединение, хотя тот же запуск `uvx` работает с MCP-клиентом Python SDK (stdio). Для отладки используем `npx @modelcontextprotocol/inspector uv run normokontrol-mcp` (как в CLAUDE.md) — работает. Причина, вероятно, в способе запуска дочернего процесса Inspector'ом; к серверу не относится.

## 2026-09-30 — Сверка правил с ГОСТ 7.32-2017 (этап 1)

Раздел 5 SPEC переписан по тексту раздела 6 стандарта. Существенные исправления:
- Структурные элементы: добавлен «СПИСОК ИСПОЛНИТЕЛЕЙ», «ПЕРЕЧЕНЬ СОКРАЩЕНИЙ» → «ПЕРЕЧЕНЬ СОКРАЩЕНИЙ И ОБОЗНАЧЕНИЙ» (6.2.1).
- Перечисления: тире, а не дефис; допускаются также цифры со скобкой (6.4.6).
- Выравнивание по ширине и нулевые интервалы до/после абзаца в ГОСТ отсутствуют — оставлены в базовом пресете с пометкой «Не ГОСТ».
- Кегль: ГОСТ требует не менее 12 пт; базовый пресет собирает в 14 пт, для проверки хранит `min_size_pt: 12`.
- Добавлены требования, которых не было: нумерация объектов в приложениях (`Рисунок А.3`, `(В.1)`), одинарный интервал в многострочных подписях, свободная строка вокруг формул, латинские буквы приложений.
- Типографика (тире, кавычки, неразрывные пробелы) — не из ГОСТ 7.32, в проверке будет предупреждениями.
- Знак в подписях «Рисунок 1 — …»: длинное тире «—» (решение пользователя 2026-09-30; в доступном тексте стандарта стоит дефис-заменитель).

## 2026-09-30 — Схема пресета: `{num}`, `sources`, наследование метаданных

- В шаблонах подписей используется `{num}` — готовый номер, а не `{n}`/`{chapter}.{n}`: вид номера задаётся `numbering`, что исключает противоречивые комбинации.
- Поле `sources` (путь параметра → пункт документа) вместо отдельного `source` у каждого правила: значения остаются простыми, `get_rules` показывает источник рядом с каждым требованием.
- `verified` и `source_docs` не наследуются: пресет вуза не может случайно получить `verified: true` от базового.
- Ресурс `normokontrol://presets/{id}` отдаёт пресет после применения наследования.

## 2026-09-30 — Базовый пресет: 14 пт и выравнивание по ширине

По решению пользователя базовый пресет `gost-7.32-2017` сохраняет кегль 14 пт и выравнивание по ширине (типовые требования вузов, помечены «Не ГОСТ»), а не сводится к минимальным требованиям стандарта.

## 2026-10-01 — Библиография: сверка с ГОСТ Р 7.0.100-2018 (этап 2)

Правила сверены с полным текстом стандарта (ifap.ru/library/gost/701002018.pdf) и памятками библиотек ТГПУ, МГТУ им. Носова, МГРИ, Псковской ОУНБ.

- Сведения об ответственности (п. 5.2.6.8): 1–4 автора приводятся все, при 5 и более — первые три и «[и др.]». В черновике ТЗ было «4 и более — первые три», исправлено. Для латинских записей — «[et al.]» (п. 5.2.6.8 г).
- Заголовок записи (имя первого автора перед заглавием) — при 1–3 авторах; при 4 и более запись под заглавием (так во всех примерах стандарта и библиотек).
- Разделитель областей — «. – » с коротким тире (п. 4.6.1; в тексте стандарта 1031 вхождение «–» против 3 «—»). Часть библиотек (ЭБС в памятке МГТУ) печатает «—», поэтому знак вынесен в пресет: `bibliography.dash`.
- Область «Текст : непосредственный / электронный» условно-обязательная (п. 4.3, 4.4.2), многие вузы её не требуют — `bibliography.content_type`.
- Точка сокращения не удваивается с «. – » (п. 4.6.11).
- Стандарт описывается с обозначения в начале записи: «ГОСТ Р 57618.1–2017. Заглавие : национальный стандарт … : дата введения 2018-01-01 / …» (приложение стандарта).
- Иностранные статьи: нумерация и страницы на языке издания («Vol. 13, no. 16», «P. 6850–6854»), п. 7.1.6, 7.4.1, 7.6.1.1.
- Для электронной книги без сайта-носителя порядок областей: URL (область примечания, 7) → ISBN (область идентификатора, 8) → вид содержания (9), по п. 4.3. В памятке ТГПУ встречается обратный порядок — следуем стандарту.
- Golden-тесты: 50 эталонов, у каждого ссылка на источник и список отличий от печатного примера (опечатки, расхождения с текстом стандарта).

## 2026-10-03 — Набор скиллов вместо MCP-сервера

По решению пользователя проект переходит с MCP-сервера на набор Agent Skills: `gost-rules`, `gost-bibliography`, `gost-document`, `gost-normokontrol`. MCP-сервер убирается из v1 (MCP-обёртка — в бэклоге v2).

- Причина: скиллы проще подключить (zip в claude.ai, плагин в Claude Code), а студенты в основном работают в Claude.
- Детерминизм сохраняется: оформление и проверку выполняют Python-скрипты внутри скиллов, Claude запускает их и выдаёт результат без изменений.
- Проектируем под песочницу claude.ai как более строгую среду. Следствия: ядро только на предустановленных пакетах (проверка окружения — первый пункт этапа 3), HTTP через `urllib`, без `docxtpl` и `pypandoc-binary`; выбор pandoc или чистого python-docx — на этапе 5.
- Поиск по DOI/ISBN без сети (песочница claude.ai) заменяется веб-поиском Claude; скрипт только оформляет.
- Теряем поддержку Cursor и других MCP-клиентов. Ядро остаётся отдельной библиотекой, поэтому MCP-обёртку можно вернуть.
- Название проекта — `normokontrol` (без `-mcp`); пакет `normokontrol`.
- Этапы перенумерованы: новый этап 3 «Переход на скиллы», бывшие этапы 3–10 стали 4–11. Работа этапов 0–2 (пресеты, библиография, 144 теста) переносится в ядро без изменений логики.

## 2026-10-03 — Библиография: ввод и новые типы (этап 4)

- Поиск: DOI → Crossref, ISBN → Open Library (`jscmd=data`, один запрос), URL → мета-теги `citation_*` (схема Highwire/Google Scholar), `og:*`, `<title>`. HTTP — `urllib` из стандартной библиотеки, таймаут 10 с, ответ не больше 2 МБ.
- Кэш ответов — на диске (`NORMOKONTROL_CACHE_DIR`, по умолчанию `~/.cache/normokontrol`), только удачные ответы; ошибки записи кэша игнорируются. `NORMOKONTROL_OFFLINE=1` разрешает только кэш.
- Найденные данные не считаются достоверными: в выводе — предупреждение «сверьте с оригиналом». Без сети скилл просит Claude найти данные веб-поиском и подтвердить их у пользователя.
- В `format_bibliography` строки с DOI/ISBN/URL разрешаются на месте; нераспознанные и ненайденные возвращаются списком «Не удалось оформить автоматически» с причиной — их структурирует Claude.
- ISBN распознаётся только с верной контрольной суммой; в записи ISBN печатается так, как его написал пользователь (с дефисами).
- Open Library почти не знает российских изданий — это ограничение источника, а не ошибка; в SKILL.md сказано искать такие книги веб-поиском.
- Crossref у глав книг ставит серию («Lecture Notes in …») перед заглавием книги: берётся последнее заглавие.
- Новые типы по примерам ГОСТ Р 7.0.100-2018: `book_chapter` и `conference_paper` (одна модель), `thesis` (имя автора после «/» — полностью, как на титульном листе), `patent` (по Поправке 2020: «заявлено», «опубликовано» полностью; изобретатели как в источнике, «Фамилия И. О.»).
- `electronic_book` и `multivolume` из черновика ТЗ не выделяются в отдельные типы: это `book` с `url`/`site` и `book` с номером тома в заглавии.
