# CLAUDE.md — правила работы над normokontrol-mcp

## Источник правды
- Полное ТЗ — `SPEC.md`. Перед любой работой прочитай разделы 1, 3 и текущий этап из раздела 10.
- Если решение расходится с SPEC.md — сначала обсуди с пользователем, затем обнови SPEC.md и запиши решение в `docs/decisions.md`.

## Порядок работы
1. Определи текущий этап: первый в разделе 10 SPEC.md с неотмеченными чекбоксами.
2. Делай только этот этап. Не забегай вперёд.
3. После каждого пункта — тесты. Этап не закрыт, пока `uv run pytest`, `uv run ruff check`, `uv run mypy src` не проходят.
4. Отметь выполненные чекбоксы в SPEC.md.
5. Коммит: `stage N: краткое описание`.
6. Короткий отчёт пользователю: что сделано, что проверить руками, вопросы. Жди подтверждения перед следующим этапом.

## Команды
- Установка: `uv sync`
- Тесты: `uv run pytest`
- Линт: `uv run ruff check . && uv run ruff format --check .`
- Типы: `uv run mypy src`
- Запуск сервера: `uv run normokontrol-mcp`
- Отладка: `npx @modelcontextprotocol/inspector uv run normokontrol-mcp`

## Принципы
- Сервер детерминированный: никакой генерации текста работы, никаких LLM-вызовов внутри.
- Исходные файлы пользователя никогда не перезаписываются.
- Описания инструментов — на английском, сообщения и отчёты — на русском.
- Правила ГОСТ не придумывать: при сомнении — пометь `TODO(verify)` и спроси пользователя.
- Полные тексты ГОСТов в репозиторий не добавлять.
- Каждое новое правило проверки — с тестом «срабатывает на плохом» и «молчит на хорошем».
